## D7 · 版面口径（2026-11-07，实测定稿）

- 扫描单位：1 PDF 页 = 1 跨页 = 左右两版；每版 **~19 列单行注文小字**（列距 ~47px，
  列间**无印刷栏线**——叠加图视觉实证，02_0029 右版；不同页 14-19 列随密度浮动）；
  **字头大字（66-90px）内嵌跨列**，不为一列所拘；注文 h0 = 37px；字头/注文高比 2.08
  （1.95-2.19，金标实测）。此前「2 列」「8 列」「14 列单行/双行」「界栏 135px」
  「2.2-2.6 倍」诸说法一律作废（各为不同页/不同尺度的误读）。
- 圈号（○ 内含数字）= 序号/音序标记；【】六角括号 = 引书名（双行夹注）——均非字头。
- 书眉 = 每版外缘「康熙字典/集名/部首/页码」，逐页真源。
- 书内页码 = 2×扫描页 − 册内偏移（PDF01 偏移 11 已实测；**每册偏移表 T2 产出**，
  此前两处各说一半的写法以此条为准）。
- kKangXi 页码是通行影印本体系，与本书扫描页无固定倍数，只作字符集上界。

## D8 · 页面形变纠偏（2026-11-07，所有者建议参考 vModou）

采用 vModou（MIT）思路的自动化重实现（`scripts/t0_rectify.py`，未复制其代码）：
强横线端点定四角 → 透视拉正 → 合理性检查失败即跳过。**几何拉正 8/8 成功 ≠ 检测收益**
（1 赚 2 亏 1 平，重采样伤细笔画）；T1 对 orig/rect 做 A/B 择优，弯曲重的版优先 rect。

## D11 · 标签链与真源口径（2026-11-08，审计 P0-1 采纳，与 D10 的关系在此厘清）

```
标签候选 = 数据集条目（提供：字面、部首、笔画、释义、正典顺序）
          + 书眉部首/页码（提供：页的部首归属与位置）
          + 扫描字头（提供：字形本体）
对齐     = 锚点锁窗 DP（锚点=双引擎一致且部内唯一命中的 OCR 读数）
标签真源 = 所有者对「框↔条目映射」的终审 + 证据链（box/char/pos/释义 可复查）
```

- **数据集不是真源，是候选序**：它有实证漏洞（玄字部缺玄）、行序需重排、扩展区条目
  不在基本区范围。D10 的「强参照不作真源」与 D11 不矛盾：D11 把数据集定位为
  「候选与顺序的提供者」，把「真」交给所有者裁决与扫描件本体。
- OCR 是对齐提示，不是标签；单字误读率 ~40% 已实测，不再作为标签依据。
- 范围：**只处理 CJK 基本区（U+4E00–9FFF）**；扩展区条目对齐但标记排除
  （所有者 r8 指示）。圈发标记、序号圈、书名括号、【】引用均非字头。
