## 0. 一句话

GLM 两天的成果里，**T0/T0.0/T1 的实测数据与工具是真实资产**；但 T2（框→条目对齐）的
**地基是错的**：它拿 MIT 数据集的条目顺序当真序，而该顺序与刻本实际阅读顺序不一致，
所以 DP 必然漂移、只能靠所有者逐半页人工读字硬拉——**这条路线在 3,869 页尺度上不可行**。
本次接手改为**结构性标注**：用 Unihan kKangXi 序 + 书眉 + 逐页计数做全局约束，
不需要逐页人工读数，且每一步都可机器校验。

## 1. 批判性复核：旧路线错在哪（证据）

### 1.1 数据集条目顺序 ≠ 刻本阅读顺序（致命）

实测样本 05_0017（辰集上 日部，书眉五畫/六畫+葉十二，所有者曾核验书眉）：

- 刻本阅读序（本次目检，R 半版→L 半版）：`昴 → 昵 → 昶 → 昷 → …`
- MIT 数据集 `entry_sequence.jsonl` 正集序：`… 昶(pos 13459) … 昴(13468) … 昵(13472) …`
  → **顺序相反**。
- Unihan `kKangXi` 的 page.position：`昴 0494.060 → 昵 0494.070 → 昶 0494.080`
  → **与刻本阅读序一致**。

结论：`t2_dpalign*.py` 全部建立在「数据集顺序 = 书序」之上；该前提不成立。
r11 的「所有者页面级校准」能"验证"01_0110R，只是把 8 个框硬压到一个错误的 8 条目切片上
（所有者只给了首/中/末 3 个锚，GLM 把「中=𠍵」这个不满足的锚忽略了）。**此路线作废。**

### 1.2 T1 切格的 precision 不够做序列记账

T1 v1.6 + G′ 过滤在 6 个半页上 precision 0.925 / 字头保留 1.000，但：
- 残差 FP（注文双字竖排粘连、圈字「增」等）足以让「逐页计数」错位；
- 60 框金标的 `iou85_frac` 0.879/0.920 是**框紧度**门槛，不是计数门槛。
计数正确性（每半页「有几个字头」恰好对）是 v3 的命门，必须单独建模、单独验收。

## 2. v3 架构：结构性标注（structural labeling）

核心思想：**字典的条目序列是已知的（Unihan 序），刻本的字头序列在版面里是单调的，
两者之间只差「每个半页有几个字头」这一个量。** 只要逐页计数正确，映射唯一确定；
书眉（集名/部名/画数）提供每页的硬校验点，错误会立刻暴露并可局部修正。

```
A. 正典序 canonical order
   正集 42,302 条 = Unihan kKangXi (page,position) 排序（覆盖率 42,298/42,302）
   + 异常点清洗（部首序违反 0.13%，组内 page 离群）
   + 同位置平局（1890 组/3,782 字，多为「重出行」正字+异体）用数据集序作 tie-break
   補遺 1,769 / 備考 4,637 = 独立序列（kKangXi 不索引其版面，用数据集序 + 人工抽样）

B. 组表 group table
   组 = (部首, 部外画数)。正集 3,563 组，组大小中位数 ~12.7 条。
   组在正典序中连续；组大小精确已知。

C. 半页候选候选字头（detector v2）
   每半页输出**有序候选**（含尺寸/方形度/边缘/标题/古文变体等打分），
   目标：字头 recall ≥ 99.5%，候选数 ≤ 字头数 + 15%。
   古文（〔古文〕弌 类大字变体）与书眉/标题块/圈字/注文粘连单列类别，不参与计数。

D. 书眉读数 header parse（3,869 个 L 半版左缘版心条；R 半版被裁）
   输出 (集名, 部名, 画数字段[]) 作为**校验点**；
   不需要它做定位——定位由 C+D 的全局计数唯一确定。

E. 映射求解
   序列 = [0006L, 0007R, 0007L, 0008R, ...]（每跨页先 R 后 L）的逐半页候选字头数；
   正典序按组表切片；累计计数与书眉逐页比对。
   不一致 → 定位到 ≤2 页窗口 → 人工/半自动二选（哪一框是 FP/漏检）→ 修正。
   目标：不一致页占比 <5%，全部可定位。

F. 出字 → 矢量化 → 组字体（复用 guangeti 脚本，venue 化 + 术语改写）
   缺字/坏字：ribbon 回落；GAN 后续。
```

**为什么这次能成**：v3 的唯一人工介入点是「计数不一致的页」，且校验点是每半页一次，
错误不会像 DP 那样静默漂移；而旧路线每页都需要人工锚。

## 4. 硬规则（沿用 PROMPT §6，补充）

1. 不做 git 写操作（add/commit/tag 归所有者）。
2. 大文件不入库；一切中间产物进 `work/`（已 gitignore）。
3. 并发 ≤10 线程/20 核：`torch/cv2.setNumThreads(1)`、`OMP_NUM_THREADS=1`。
4. 用 `.venv/bin/python`（3.12）；缺库时 `python3 -m pip install --target` 到 `.venv` 之外的自有目录，不要污染他人环境。
5. **不得用数据集顺序做真序**（本文件 §1.1）；不得用整行 OCR/整行序列当标签真源。
6. 判定参照只能是刻本字头本身；所有数字必须落盘、可复算、写清口径。
7. 术语：刻本/刊本/字头/注文/古文/书眉/版心。

## 5. 关键实测事实（新增，供各流直接使用）

- 阅读序：**每跨页先 R 半版、后 L 半版**；版内列右→左，列内上→下。（D14，本次目检复核）
- 书眉在 L 半版**左缘**（版心，可能被裁掉一部分）；R 半版右缘版心基本被裁。
  书眉字段：康熙字典 / 集名卷 / 部名 / 画数字段（跨分界页两个）/ 葉码。
- **书眉画数 = 部外笔画数**（例：日部「五畫」= 总笔画 9 的组，昴/昵/昶）。
  数据集 `stroke` 字段 = **总笔画**，映射：`部外 = stroke − 部首笔画`。
- 古文变体：刻本在条目注文里把〔古文〕X 印成**大字形**（约 1.7–1.75×h0，小于字头 2.08×），
  且前方有小字「古文」标签。**不是数据集条目**，不能计入「每页字头数」，
  但作为字形样本可以带标签复用。
- 一/乙/亅 类扁平字头要按「宽高比的宽」判，不能用高度。
- 扫描页 = 跨页；PDF 内页号 → 该册内叶序，PDF01 有 葉码=扫描页−5 的实测（D14）。
