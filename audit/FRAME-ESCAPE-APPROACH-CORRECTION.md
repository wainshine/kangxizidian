# 框线逃逸：方法纠正（切之前排除，而不是切进去再擦）

> 触发：owner 指出「边框线本来就不该切进切片；切之前就应该排除；切进去再排除容易误伤」。
> 结论：**owner 的判断正确**。此前两次尝试（v2.5.9 候选）都是「先按 box+pad 裁进来 → 再擦线/清理」，
> 属于错误的层；该版本已**撤回**（`release/_withdrawn/KangXiKai-v2.5.9-posthoc-erase/`），不作为发布候选。

---

## 1. 为什么「切进去再擦」是错的（实测证据）

以 嗃 #308（02_0074 R，右半版左下角）为例：

| 方案 | 做法 | 结果 |
|---|---|---|
| A. 后处理擦线（v2.5.9 候选） | 裁 box+pad → 二值 → 用版面元素 mask 擦线 → 块掩膜 → 清理 | 线区被擦，但**擦除范围与真实框线不完全重合**：细内框线/断线漏检时线仍在（嗃 最终 ratio=1.0 → 与旧字形完全相同，线还在）；过度擦时又可能伤及贴线笔画；且 2,302 字逐一靠「ratio/IoU 闸」兜底，回退 11 字说明闸本身在打补丁 |
| B. **切前排除**（正确层） | 先求「版框内正文区」content box → 裁切时直接 clip 到 content box → 框线/黑带/角部**从不进入 ink** | 嗃 demo：框线与左下楔形完全消失、字形完整（`work/review/preclip-gao-demo.png`） |

后处理的本质问题是：**线一旦进入二值图，就和字身墨混在一起**，之后所有判断都只能靠形状启发式
（细/长/断/贴边/参考支持），必然在「漏擦」和「误擦」之间摇摆——这正是该问题反复 4–5 次的机制。

## 2. 正确方案：版框内正文区（pre-cut content region）

### 2.1 几何
康熙刻本每半版有**双线版框**（外粗内细）；正文在框内，框线与正文间只有很小间距。
对每页/每半版求 `content box`：
- 注文小字组件 bbox → 正文主体范围（字头比小字 wider/higher，故向外扩 ~60px 覆盖字头）；
- 框线检测：长游程（行/列内连续墨段 ≥ 0.15×半版宽/高）+ **孤立性**（线两侧 5–9px 基本空白——
  框线两侧是白边，文字行/列两侧有字，借此区分真框线与文字行）；
- 页边黑带单独钳制（外缘 12% 内强墨行/列）；
- 有微旋转时先按 Hough 长线中位角旋转（本批页面 0.2–0.4°），在旋转空间求 box，再逆变换回原图坐标。

### 2.2 裁切
`font_norm.vectorize_box(..., content_quad=...)`：渲染 box+pad 后，**在二值图之前**把 content box 外的像素
置零（clip mask 由 `page_frames.clip_mask_page` 按 300dpi crop 坐标生成）→ 后续块掩膜/清理只看到正文墨。
框线、页边黑带、四角楔形**在源头被排除**；主链**不需要**任何「按形状删组件」的擦线步骤。

### 2.3 与 2×2 格块的关系
content box 只负责「版框边界」；格块掩膜继续负责「块外邻墨/注文」。两层职责分开，互不替代。

## 4. 为什么还不能直接全量重切（必须先解决的两件事）

1. **检测健壮性**：部分页面框线在扫描时被裁掉（只有单侧框线）或字头紧贴内框线（如 鬼 12_0069、
   臀 08_0291 的边界），content box 需按页自适应：框线缺失侧用「小字 bbox+60 / 页边黑带」兜底，
   并保证 content **至少**覆盖全部字头（当前用少量抽样验证，尚未全量证明）。
2. **无损验证闸**：全量重建后必须证明「content clip 只删框线、不删字身」：
   - 内容缺失闸 vs v2.5.8：0 缺损；
   - 新增 **frame-escape 闸**：逐字检查 content box 内是否还有框线像素（应为 0）；
   - 逐字 diff 审计：新旧字形差异像素必须落在「框线检测 mask」内（否则回退该字）；
   - top-200 目检（owner 之前标记过的字 + 嗃/肩/臀/鬼/握 等样例）。
