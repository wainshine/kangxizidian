## 二、v2.0.1 的修复方式

1. **同框唯一性**：`lead_vlm_confirm.py` 在合并后按 (page,half,box) 聚类，冲突框**两侧标签全部剔除**（保守，不做单侧裁决），输出 `same-box-conflicts-v201.json`（**49 框 / 98 字**）；最终 union **同框冲突 = 0**。
2. **剔除非 canonical 字**：**238 字**全部剔除（列表随包），字体只含康熙字头集内的字。
3. **严格过滤**：`音切开头 + score1≥0.4 + margin≥0.1 + 转写长度≥4` → A 类 4,045 行、B 类 6,771 行通过；入集 A 4,045 / B 6,115 字。
4. **QA 加硬闸**：`font_qa.py` 新增「同框多字 = FAIL」（若 manifest 带 page/box）；v2.0.1 通过。
5. **披露**：conflicts / 非 canonical / QA 剔除 三份清单 + 覆盖口径双报（含 ∩canonical 口径）+ 验证精度表（分阈值 n/prec）。

## 三、v2.0.1 数字（诚实口径）

- 字体：**17,631 字形**（v2.0 为 20,611；减少来自 238 非字头 + 98 冲突 + 严格过滤 + QA 剔除）；
- **基本区 ∩ 16,567 目标集 = 10,782 / 16,567 = 65.08%**（QA 前，QA 后见随包 coverage-detail）；
- 新增字精度：严格规则下 **~85-88%**（n=14-15，宽 CI）；A/B 类中仍有尚未验证的比例，已在 README/RELEASE-NOTES 披露；
- 无同框冲突、无非字头字、全流程可复算（scripts + sha256）。

## 四、结论与后续

- 审计的 P0 全部为真且已在 v2.0.1 修复；P1 已修/已改口径；P2 已修关键项。
- 精度问题（v2.0 宣称 97% 实际 ~75-88%）是本轮最重要的教训：**验证集选样偏差**导致高估。v2.0.1 起所有精度数字必须来自 `lead_fp_validate.py` 可复算输出。
- 后续（v2.1 方向）：对中间置信带（score 0.3-0.4 / margin 0.05-0.1，约 3,200 行）做人工目检工单，逐条确认后入库，可在保证精度的前提下补回 ~1,500-2,500 字。
