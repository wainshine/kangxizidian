## 二、发现的问题（按严重度）

### P1-1 README 缺标准与精度敞口（v2.4.0 包内）
- `README.md` 由脚本模板生成，**不含** headword-only 标准声明、精度敞口（~1,400-1,500 字）、GAN 补全计划；
  这些只在 `PROVENANCE.md`/`RELEASE-NOTES` 里。使用者只看 README 会漏掉关键披露。
- **修复（v2.4.1）**：改用显式 README 模板，三项写入，覆盖数字自动填入。

### P2-1 `contours_override.json` 静默注入风险
- v2.2 加的 override 机制在「映射含该字」时即注入 v2.0.1 轮廓（二/顔 曾用）；
  v2.4.0 已按标准剔除这两字，但 override 文件仍在——若未来映射重含「二/顔」，会**绕过 headword-only 过滤**静默注入。
- **修复（v2.4.1）**：override 仅在条目标记 `from_v201_glyph` 时生效。

### P2-2 孔洞统计口径易误读（无缺陷但需说明）
- 同一 `font_qa` 复跑：v2.1.2 lost **475** → v2.2.0 **1594** → v2.4.0 **1500**；
  抽查典型字（日/目/月）显示这是**楷体刻本的开放字腔**（如「日」中横不接右竖 → 1 个连通腔），
  与宋体（2 腔）本就不应相等，v2.2 起矢量化更保真后差异变大。**属风格差异，不是丢孔**；
  `docs/QA.md` 已写「仅诊断」，本次补记版本漂移原因。
- 复核：v2.2.0 包内 `qa-report` 的 holes=1594 与复跑一致（此前我引用的 31 来自另一构建的中间报告，已废弃）。

### P2-3 其它（记录，不阻塞）
- `glyph_ok` 渲染近似检查的 y 映射/孔洞填充与 font_qa 口径不一致（仅用于过滤辅助，最终以 font_qa 为准）；
- 工作区 QA 报告目录存在多版本中间态（`work/font/build/qa_*`），易被误引用 → 以发布包内报告为准；
- 无自动化回归测试（视觉/数字核对仍靠脚本+人工），建议后续加 CI 脚本。
