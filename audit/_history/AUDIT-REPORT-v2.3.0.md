## 二、P0：v2.1 质量过滤误删 131 字——字体自 v2.1.0 起**没有「一」**

**事实链（全部复现）：**
1. v2.0.0/v2.0.1 有「一」，其矢量化字形 bbox=[120,218,880,581]（正常字头形，QA PASS）；
2. v2.1 `lead_glyph_filter.py` 以「原始框 p90 笔画宽 ≥4.5 或短边 ≥130（300dpi）」判字头级。
   「一」的框是「字头+注文」合并框（01_0007R [1777,1385,1836,1461]，59×76@150dpi，
   p90=2.87、短边 118——注文小字主导了笔画宽统计）→ 判为非字头；
3. charalign14 对「一」只有这同一个框 → 无替代 → **丢弃**；
4. 同批被丢 131 字（基本区 118），其中大量最常用字：
   **一、合、炎、春、氣、谷、律、秦、夷、毅、梁、答、刻、厘、勝、伶、佩、倪、姑、媒、援、社、種、盛、與、徐、曼、愈、屬、辟、辨、被、裔、疏、碎、瞳、磬、棺、植、棘、灌、瓣、斟、筍、丿、丨、幺**…
5. v2.1.0 → v2.3.0 全部版本缺「一」（cmap 无 U+4E00，fontTools 复核确认）；v2.0.1→v2.3.0 累计丢失 **349 字**
   （131 过滤丢弃 + 62 个 v2.1 QA 剔除（今/吟/拜/相/盲/枚…）+ 48 个 v2.2 保真断笔剔除 + 杳）。
6. 披露不足：RELEASE-NOTES/COUNTS 只写「131 字丢弃」，并解释为「剔除注文小字→只含字头级字形」；
   **从未点名「一/合/春/氣」等常用字缺失**；覆盖率按字符个数统计，丢「一」与丢「𪗭」权重相同，
   63.53% 的数字完全掩盖了严重性。v2.3 字体实际无法渲染「一」「合」「春」「氣」等常用字。

**根因（判定标准的测量对象错了）：**
- 过滤器测的是**原始框墨迹**的 p90（合并框被注文细笔画主导 → 偏低），而不是**矢量化结果**；
- v2.0 的事实证明：这些合并框经 `font_norm` 矢量化后得到的是正常字头字形（bbox 全 em、QA PASS）。
  正确的判据应放在矢量化输出上（字形 bbox 占 em 比例/主成分大小），而非原始框。

## 八、改进方案（按优先级）

1. **恢复被误删的常用字（最高优先）**：对 131 丢弃字改用「矢量化结果判定」重判——v2.0 已证明其
   字形可用，可直接回填 v2.0 字形或从合并框重新矢量化；至少先恢复
   **一/合/炎/春/氣/谷/律/秦/夷/毅/梁/答/刻/厘/勝/伶/佩/倪** 等高频字（v2.0.1 的 build cache
   中轮廓仍在，回填成本很低）。发布说明中须点名「缺失常用字」及数量。
2. **QA PASS 口径**：manifest 与字体同源（剔「杳」后重打包并重跑 QA）或如实标注 FAIL；
   RELEASE-NOTES 数字改为由 manifest/coverage-detail 自动生成，杜绝手抄。
3. **打包流程**：打包后冻结目录；任何后打包改动 → 重算 SHA256SUMS + 重打 zip + 重跑 zip 自检；
   把「120 字抽查图」等所有承诺随包的文件列入打包清单校验。
4. **过滤判据改到矢量化输出上**：`lead_glyph_filter` 的 p90/尺寸判定应作用于 `font_norm` 产出的
   轮廓（bbox 占 em 比例、主成分尺寸），避免合并框被注文细笔画误导。
5. **替代框加证据**：alt/qa_retry 换框的字跑注文指纹或 OCR 双票验证新框；无证据者随包标注数量；
   版本间「新增/删除/替换」三份 diff 清单自动生成随包。
6. **抽样复核 clean_cluster / prune_edge_contours**：针对远距独立笔画（氵/灬）、细长主体（一二三）、
   贴边小笔画（刃丶）三类字形做 100-200 字样张目检后再发下一版。
7. 清理死代码（`seconds = sys.argv[1:]`、重复 import 等）；`lead_vlm_confirm.py` 的 kx 加载仍用
   setdefault 只取同字首条注文（多部首同字 1,675 条被忽略），建议全条参与匹配。

## 九、结论

第二轮复核确认：**上轮 P0/P1 已实质修复**（同框双标、覆盖率口径、管线脚本化、验证口径），

但 v2.1 起的质量过滤引入了一个新的严重回归：**字体自 v2.1.0 起缺「一」，连同约 130 个常用字**，
