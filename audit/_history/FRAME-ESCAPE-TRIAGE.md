## 2. 机制链条（逐步实测）

| 步骤 | 实测结果 |
|---|---|
| ① 旧 mapping 框 | `[1062,1338,1186,1469]`，紧贴内框（左边界 x≈1060-1062、下边界 y≈1465-1469） |
| ② 2×2 块 | `[1072,1354,1173,1452]`：**左边界压在竖直内框线上、下边界压在下侧内框线上**（线宽 2–3px，约一半落在块内） |
| ③ 页级框线 mask | 形态学开运算（横核 0.35×页宽=662px、竖核 0.45×页高=738px，无 gap/倾斜容忍）；这条内框线在页上总长约 950px 但**不连续**（被字形/注文/断点打断）→ 核要求连续 738px → **不命中**；外框厚黑带也因断点不命中。**crop 内 mask 覆盖 = 0 像素**（实测） |
| ④ 块掩膜 | 只丢块外像素；框线在块内的一半全部保留 |
| ⑤ 清理链 | `clean_cluster/clean_ink` 以「主簇/中心区」为判据，框线与字身同处块内中心区 → 不删 |
| ⑥ 归一化 | 墨迹 bbox 含框线 → 框线随字形一起矢量化并归一化 → 进入成品字形（细线 + 三角楔） |

**一句话**：不是「切多了」，是**该擦的线没擦掉，而 2×2 块边界恰好与线重合**。

## 3. 为什么这个问题反复出现 4–5 次

每次修的是不同子类，没有覆盖「块边界与细框线/界行重合」这一类，也没有全库机器闸：

| 轮次 | 当时修的子类 | 手段 | 对这一类是否有效 |
|---|---|---|---|
| v2.4.x 早期 | 外框厚边/页边黑带 | `strip_border_lines`（贴边带删除） | ✗（只处理页边带，且后被禁用） |
| v2.4.13–16 | 注文括号/小块/邻墨 | `refgate_clean`（参考闸外科清理） | ✗（参考字体对「线与字的相对位置」不敏感） |
| v2.5.0 | 块外杂墨 | 2×2 格块掩膜 | ✗（块内的框线留着） |
| v2.5.1 | 页框线 | 形态学长线 mask（严格轴对齐） | **部分**（粗/连续线有效，细/断线漏检） |
| 每次验收 | random120 抽样 / owner 100 字目检 | 人工 | ✗（120/17,007 抽样命中率极低，发现不了 13% 的系统性问题） |

**根因**：修的是症状层，缺少「源头线检测 → 逐字逃逸统计 → 全库闸」的闭环；验收依赖抽样，抽不到就等于没发现。

## 5. 类级修复方案（已原型验证）

### 5.1 新检测器 `detect_page_rules`
双通道并集（防漏检）：
1. **Hough 近轴长线**：±2° 容差、`minLineLength=0.12×页维`、`maxLineGap=12`、
   沿线 5×5 邻域墨占比 ≥0.5（**防把文字行连成线**，实测 02_0074 上 56 条/110k px）；
2. **细长连通域**：长 ≥28% 页维、厚度 ≤14px（覆盖无倾斜断线）；
3. 与现有 frame mask 取并集并膨胀 1–2px。
原型实测：嗃 crop 内新增 1,675 px 覆盖（正好是内框线+外框段），重切后字形干净（对比图第三列）。

### 5.2 重切与验证
1. cache tag 升 `v320`，全量重矢量化 17,029 字（8 workers，约 10 分钟）；
2. **误删审计闸**（新）：重切前后逐字 diff，要求「被删像素 ⊆ 规则线 mask 膨胀域」，否则回退该字（防误删真笔画）；
3. `scan_frame_escape` 纳入 `release_gate`：阈值 0，报告随包；
4. 渲染层二道闸：字形 mask 上检测细长直线段（Hough），命中即 FAIL；
5. 验收：嗃 + top-100 目检；逃逸 2,302 → 0（或仅剩误报）；内容缺失闸 0；QA PASS；出 v2.5.9。

### 5.3 风险与工时
- 风险：Hough 误检文字行 → 沿线墨占比 + 长度阈值控制；误删真笔画 → 5.2-2 审计闸 + 逐字回退；字形变化约 1–2k，覆盖统计不变。
- 工时：检测器 30min + 扫描 5min + 全量重建 15min + 闸入链 20min + 验证 20min ≈ **1.5–2 小时**。

## 6. 结论与建议

1. 嗃 的问题**不是切多了，是框线没擦干净 + 块边界压线**；用户直觉「只切蓝框」方向正确，但根本解决要靠**源头线擦除**（不能靠缩小框，会切掉真笔画）。
2. 已把这一类做成**可量化、可回归**：检测器 + 全库逃逸扫描 + 双重闸。
3. **建议立即按 §5 执行 v2.5.9**（约 2 小时），修复后 `scan_frame_escape` 归零再谈签收——这是当前「框线反复出现」问题的总开关。
