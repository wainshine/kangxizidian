# 根因分析：框线/字形问题为什么反复回归（不是单字问题）

> 触发：owner 指出 v2.6.0 缺陷台账中「勤」仍有框线，并明确要求「找根源，不要再修单字」。

## 1. 直接原因（已复现）

- `勤`（01_0194 L）在 v2.6.0 中来自 **`precut_restore` 恢复层**（把 v2.5.8 旧字形整字拷回）；
- v2.5.8 旧字形由**旧架构**生成（裁后擦线），其字形本身带框线；实测：
  - 新架构基座（切前排除）的 勤：**干净、完整**（无框线，`/tmp/qin_base_vs_old.png` 右）；
  - 恢复进来的旧 勤：**带顶部框线**（左）；
- 结论：**restore/overlay 这类「整字拷回」层本身就是问题的回流通道**——每引入一次恢复，就把旧架构的框线/残片带回来一次。v2.5.6 的 1,602 字 overlay 是同一机制。

## 2. 为什么需要 restore 层（更深一层）

- 新架构从 **mapping box** 全量重建；但 v2.5.2–v2.5.4 的 1,602 字修复（扩框、切偏重选、补件）**只改了 TTF，从未回写 mapping**；
- 于是新重建按旧 mapping box 切 → 字形与 v2.5.8 不同（残缺/偏移/缩放差异）→ 又用「恢复旧字形」去补 → **两套真源互相拉扯**；
- mapping box 质量数据：17,007 个框中 **911 个宽度 <70**（中位 81×80，而 2×2 格块约 95×92）→ 框普遍偏小/偏位，这正是「切不全文、反复修复」的结构性来源。

## 3. 第三层：特殊页的版面结构

- v2.7.0 候选（用重建 mapping box + 切前排除全量重建）实测：
  - QA PASS；内容闸 vs v2.5.8 = **48 字**；框线逃逸 = **60 字**；
  - 集中检查发现：这些字集中在**卷首/目录/牌记/双栏等特殊版式页**（如 01_0009 卷首、01_0208/01_0218 目录页），
    这些页面的「2×2 格点 / 版框正文区」假设不成立或检测不稳 → content box 偏大/偏小 → 框线残留或字身被裁；
- 说明：框线问题的残余不是「某些字」，而是**一类页面**（特殊版式页），必须按页面版式类别处理，而不是逐字修。

## 4. 根因结论（一句话）

**三套真源并存**（旧 mapping box、旧修复字形 overlay/restore、页级框线 mask）导致每次修复只动一层、其他层把问题带回来；
必须收敛为**单一真源 + 单一管线**：
1) mapping box 由「2×2 格块 + 版框内正文区 + 源墨」统一生成并回写（不再有修复 overlay）；
2) 裁切阶段排除版面元素（pre-cut），清理阶段不做形状启发式删除；
3) 特殊版式页单独建类处理（卷首/目录/牌记），不与正文页共用格点假设。

## 5. 已执行的类级修复（v2.7.0 候选，尚未发布）

- 删除 restore/overlay 层（不再拷回旧字形）；
- 新增 `scripts/rebuild_mapping_boxes.py`：全量重建 17,007 个 box（块内主簇墨迹 bbox + 本地框线带剔除 + content 钳制），
  产出 `work/lead/mapping_verified_all40.jsonl`（**单一真源**）；
- 从新 mapping 全量重建（cache v330）：QA PASS；框线逃逸 60、内容闸 48（均为上述特殊页类）；
- 这些结果不再用单字补丁掩盖。

## 6. 下一步（类级）

1. **页面版式分类器**：正文页 / 卷首序页 / 目录页 / 牌记页 / 补遗页（用现有 ink 投影+格点稳定性判断）；
2. 特殊页类使用独立策略（如目录页不切字头、卷首页单独版面模型），正文页保持 2×2 + pre-cut；
3. 重建后跑：内容闸 0、框线逃逸 0、缺件扫描（应显著低于 592）、top-200 目检；
4. 全部通过才发布；**不再使用任何 restore/overlay/单字修复**。
